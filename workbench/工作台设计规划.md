# 集团经营工作台 · 功能模块与交互逻辑设计

> 适用主体：新能源项目（风电／光伏／充电场站）+ 大交通机电（工程与设备供应）+ 网约车平台运营 + 新能源车销售
> 使用者：集团一把手及分管领导（同时向下兼容事业部与项目层）
> 文档版本：v4.0（2026-08-08 更新：科技感 UI 重构 · 项目要素梳理 · 合同全生命周期管理 · 业财一体 · 业务人员管理与业务费用整合 · **项目地图与数字孪生 · 业务费用并入损益口径 · 人员绩效排名 · 登录与多设备协同后端**）

---

## 一、先想清楚：这个工作台到底解决什么

多元化公司的管理者，痛点从来不是"没有数据"，而是这三件事：

**1. 数据分散在四套逻辑里，脑子要不停切换频道。**
新能源看的是"手续和节点"，机电看的是"中标和回款"，网约车看的是"单量和合规"，卖车看的是"线索和库存"。四条线的成功指标完全不同，硬塞进一张报表只会互相稀释。

**2. 真正决定成败的是"卡点"，但卡点不在报表里。**
一个 100MW 项目卡在供电公司的接入评审，报表上只显示"前期手续阶段 46%"，看不出已经卡了 43 天、快要错过年内电价窗口。你们业务里反复出现的"跑动"，本质就是在消灭这些卡点——它必须被单独管理，而不是藏在项目进度条后面。

**3. 看到问题和解决问题之间，隔着一整套流程。**
发现异常 → 打电话问 → 找人 → 布置 → 忘了跟 → 下个月发现还没办。这个链条断在哪，管理效率就损失在哪。

**所以这个工作台的设计原则只有一句：所有数字都不是给你"看"的，是给你"派活"的。**

---

## 二、总体架构：四层

| 层级 | 内容 | 使用频率 |
|---|---|---|
| **L1 决策层** | 经营驾驶舱（红黄灯预警、待我审批、今日跑动、现金与回款） | 每天 5 分钟 |
| **L2 业务作战层** | 新能源项目 / 大交通机电 / 网约车平台 / 车辆销售 | 每周 1-2 次深看 |
| **L3 共性能力层** | 跑动作战台 / 资金与风控 / 政企与客户关系 | 按需 + 每日跑动 |
| **底座** | 项目主数据、组织与权限、审批流、消息中心、移动端 | 无感 |

关键判断：**不要把四条业务线做成四个独立系统再拼首页**。业务层各说各话没关系，但预警、跑动、资金、审批必须是全集团统一的一套，否则工作台会退化成"四个报表的入口页"。

## 三、功能模块设计

### 模块 1 · 经营驾驶舱（首页）

**回答一个问题：今天我必须管什么。**

| 区域 | 内容 | 设计要点 |
|---|---|---|
| 顶部 KPI 带 | 在推项目、年度签约额、经营性现金流、应收逾期、今日跑动、待我审批 | 6 个封顶。每个可点击下钻，禁止放"看着好看但不驱动决策"的指标 |
| 今日必须处理 | 红黄灯预警清单 | **按"影响金额 × 逾期天数"排序**，不按时间倒序。红灯不超过 5 条，超了说明阈值设松了 |
| 今日日程与决策 | 会议、外出、待决策事项 | 每条都挂关联项目，点进去就是项目详情 |
| 四业务线健康度 | 每线一张卡：健康分 + 趋势线 + 3 个核心指标 | 健康分由 5-8 个指标加权，权重可配置。这是你判断"该往哪投精力"的抓手 |
| 收入与现金流 | 12 个月柱线组合图 + 收入毛利结构 | 收入和现金流必须同屏，多元化公司最容易出的问题是"有收入没现金" |

**健康分建议权重（可调）**

- 新能源：手续按期率 30%、投资执行偏差 20%、并网节点达成 25%、场站利用率 15%、安全 10%
- 大交通机电：进度达成 25%、中标率 20%、回款及时率 30%、库存周转 15%、质量安全 10%
- 网约车：单量趋势 25%、**合规率 30%（一票否决：低于 90% 直接判红）**、单车贡献 25%、安全投诉 20%
- 车辆销售：目标达成 30%、线索成交率 20%、库存车龄 25%、单车毛利 25%

### 模块 2 · 新能源项目

**核心视图是两个：管道漏斗 + 手续矩阵。**

- **项目开发管道**：资源摸排 → 政府对接 → 指标获取 → 前期手续 → 开工建设 → 并网投运，按**容量（MW）**而不是项目个数统计。每级显示转化率，转化率最低的那一环就是明年的战略重点。
- **前期手续矩阵**（本模块最有价值的一屏）：横轴是手续类型（备案核准、用地预审、环评、林草水保、接入系统、并网协议、施工许可），纵轴是项目，每格用五色标记：已办结 / 办理中 / 临近期限 / 超期卡点 / 未启动。**每一格背后都挂着责任人、对接单位、关键人、期限**，点开就能派单。
- **项目台账**：阶段、进度、投资执行（已投/总投）、责任人、风险标签。
- **充电场站运营**：充电量趋势、单枪利用率分布、场站盈利红黑榜。场站是"小而多"的资产，必须按单站算账，**利用率低于 8% 的站要有止损或改造决策**。

> 建议增加一条反馈闭环：把已投运场站的**实际利用率**回写进新场站的选址模型。原型中充电场站包 IRR 偏差 -2.8pt，根因就是选址阶段车流量预估过于乐观。

### 模块 3 · 大交通机电（工程 + 设备供应）

这条线有两个身份——**既是工程承包商，又是设备供应商**，账要分开算。

- **商机到中标漏斗**：项目信息 → 立项跟踪 → 投标报名 → 正式投标 → 中标签约，金额与个数双口径。**必须做失标归因**（价格 / 业绩门槛 / 关系 / 废标），否则中标率只是个结果数字。
- **在建标段甘特**：计划 vs 实际双条，滞后自动飘红。机电专业交叉多，节点滞后要能穿透到"卡在哪个分项"。
- **设备供应链看板**：待发货 → 在途 → 待安装 → 待验收 → 待结算，按金额跟踪。**重点做"呆滞 + 缺口"双向预警**——机电物资最典型的问题是一边压着几百万呆滞库存，一边关键物资缺货停工。
- **应收账龄与回款**：分 30/60/90/180 天以上，质保金单列。

> 交通项目的回款有个特点：**很多进度款是"具备申报条件但没人去报"**。工作台要单独设一个指标叫"可申报未申报金额"，这是纯粹靠管理动作就能拿回来的现金。

---

### 模块 4 · 网约车平台

强监管行业，**合规是一票否决项，必须放在和经营指标同等位置**。

- **运力**：注册司机、活跃司机、活跃率、在营车辆、上线率。
- **订单**：日单量、GMV、完单率、应答率、客单价。
- **合规专区**（红色高亮）：平台经营许可、车辆运输证、驾驶员证三证合规率 + 到期预警清单 + 监管数据推送成功率。**双证合规率低于监管红线直接触发红灯并推送至一把手。**
- **司机生命周期漏斗**：注册 → 证件齐全 → 车辆到位 → 首单 → 次月留存。这条漏斗直接连着模块 5 的卖车业务。
- **单车日经济模型（关键）**：流水 → 平台抽成 → 司机补贴 → 获客运营 → 技术合规 → 单车贡献。补贴是最大的可调变量，要能做敏感度测算。
- **运力供需热力图**：星期 × 时段，标出缺口时段。这是补贴投放的靶点，避免全时段撒钱。

---

### 模块 5 · 新能源车销售

- **转化漏斗**：线索 → 有效跟进 → 到店 → 试驾 → 订单 → 交付，每级转化率对标行业值，自动标出断点。
- **渠道来源与质量**：不看线索量，看**各渠道成交率**。
- **库存与车龄**：0-30 / 31-60 / 61-90 / 91-120 / 120 天以上分布 + 资金占用。超 90 天强制进入促销或调拨决策流。
- **业务协同池（你们独有的优势）**：网约车平台的在营司机就是最精准的购车客户库。工作台要单独设一块：可置换司机数、意向建档数、以租代购在贷余额与逾期、本月司机购车转化台数。

> 原型数据显示：平台司机线索成交率 18.9%，是外部投放线索（6.6%）的 **2.9 倍**，但只占线索量 22%。这是四条业务线中协同价值最高、最容易被忽略的一条通道，值得单独设指标、单独设考核。

### 模块 6 · 跑动作战台（差异化模块，建议优先建）

这是把你们"跑动"这件事**从个人能力变成组织能力**的地方。

**事项台账**——每一条必须回答四个问题：

| 卡在哪 | 卡了多久 | 下一步谁去 | 什么时候办完 |
|---|---|---|---|
| 对接单位 + 关键人 | 自动计算滞留天数 | 责任人 + 协办 | 期限 + 升级规则 |

**自动升级机制（核心规则）**

| 滞留时长 | 动作 |
|---|---|
| 超过 7 天 | 自动升级至分管领导，推送提醒 |
| 超过 15 天 | 自动升级至董事长待办 |
| 超过 30 天 | 强制进入下次经营例会议题，不可关闭 |

**政企与客户关系图谱**
- 关键单位覆盖度：按"是否有稳定对接人"打分，暴露薄弱环节。
- **承诺台账**：对方的口头承诺也要记（谁、承诺什么、什么时候），到期自动提醒。这是跑动最容易流失的资产。
- 跑动效能排行：**不看跑了多少次，看办结了多少事**。拜访量高但办结率低的人，要么事项难度大，要么跑动质量有问题，需要区分。

**移动端**（跑动人员的唯一入口，30 秒完成）
现场签到定位 → 选择进展标签（有进展 / 需补材料 / 遇阻 / 已办结）→ 一句话记录 → 拍照回执 → 指定下一步和期限 → 提交。提交即回写，桌面端红灯自动转绿。

### 模块 7 · 资金与风控

- **未来 13 周资金预测**（比任何历史报表都重要）：周净流 + 期末余额 + 安全线。跌破安全线提前预警，给足腾挪时间。
- 应收账龄、应付、保函与授信占用、资产负债率。
- **投资与回报跟踪**：已投运项目"测算 IRR vs 实际 IRR"对照。偏差大的项目要倒查测算假设——这是防止同样的坑踩第二次的唯一办法。
- **跨业务线合规证照总表**：电力业务许可、机电总承包资质、网约车平台许可、汽车销售授权、安全生产许可，统一到期提醒。资质过期对投标资格是致命的。

### 模块 8 · 项目图纸 / 预算 / 概算（项目主数据）

挂在**项目详情页**内，是四个业务线工程的共性底座——风电/光伏/场站要图纸与概预算，高速公路/国省干线机电工程更要图纸、预算与概算，且存在"施工图 → 预算 → 结算"逐层受控的逻辑。原型把它做成一个**三档切换的文档库 + 概预算对比控制**。

**顶部控制带（4 个 KPI，点击直达对应档）**

| KPI | 含义 | 点击动作 |
|---|---|---|
| 设计概算总额 | 全费用口径，分科目 | 跳「概算」档并展开概预算对比 |
| 施工图预算总额 | 全费用口径 | 跳「预算」档 |
| 预算 / 概算 | 预算较概算的占比 | 跳「概算」档看对比 |
| 图纸版本 | 已审定 / 评审中套数 | 跳「图纸」档 |

**三档内容**

- **图纸档**：图纸名称、类型（总图/电气/结构/线路/接入系统/BIM）、版本、阶段（初设/施工图/竣工）、编制单位、日期、状态（编制中/评审中/已审定/作废）、编制人。点「查看」看版本历史与关联审批；点「＋ 新增图纸」在右侧抽屉填表即入库，设计院上传新版本自动通知校核/审批人，版本留痕可回溯。
- **预算档**：预算名称、科目（设备购置/建安工程/其他费用/预备费/全册）、金额（万元）、版本、日期、状态（编制中/审核中/已批准）。
- **概算档**：概算名称、科目、金额、版本、编制依据、状态。**概算档下方内置「概预算对比表」**——按费用科目列概算、预算、偏差（万元）与偏差率，预算超概即飘红，整体偏差率一目了然。

**两条管理红线（建议做成规则）**

1. **预算不得突破概算**：任一科目预算 > 对应概算，自动触发红色预警并锁定，需董事长审批（走概预算调整专题）后方可执行。这是工程投资控制最基本的纪律。
2. **图纸版本必须受控**：现场施工/采购所依据的版本必须与"已审定"最新版一致，错版施工或按作废版采购是重大质量与成本事故。工作台以"已审定"状态 + 版本号作为唯一有效版本。

**与原型主线的关系**：图纸/预算/概算的审核、变更、超概，都通过抽屉里的"派单/审批"动作闭环，并回写驾驶舱与资金风控（如超概会进入投资与回报跟踪的偏差项）。它不是独立的文档柜，而是工程成本与质量控制的抓手。

## 四、交互逻辑

### 主线 1：预警 → 下钻 → 派单 → 闭环（最重要）

```
信号自动触发  →  一键下钻定位  →  现场直接派单  →  跑动留痕销号
（超期/滞后/       （数字到项目、      （责任人+期限+      （移动端回填，
  逾期/到期）        到单据、到人）      升级规则）          红灯自动转绿）
                                                              ↓
                                              自动回写驾驶舱，形成回路
```

设计要点：**派单入口必须出现在你发现问题的那一屏**，不能要求"回到任务模块新建任务"。你看到问题的那一刻，就是决策成本最低的时刻。

### 主线 2：三级下钻，任何数字都可穿透

```
指标（4,180 万应收逾期）
  → 列表（按客户/账龄/业务线拆解，可切换维度）
    → 单据（具体合同、发票、催收记录、责任人）
      → 行动（派单 / 批示 / 加入例会议题）
```

每次下钻都在**右侧抽屉**打开，不跳转页面——保持上下文，随时关掉回到全局。抽屉里同时显示**数据口径与来源**（来自哪个系统、更新频率、统计口径、责任部门），避免开会时争论数字真假。

### 主线 3：角色视角切换（一套系统，三种看法）

| 角色 | 默认落地页 | 数据范围 | 核心动作 |
|---|---|---|---|
| 董事长 | 经营驾驶舱 | 全集团 | 审批、批示、升级事项 |
| 分管领导 | 所辖业务线专题 | 本条线 | 派单、督办、资源协调 |
| 项目/部门经理 | 我的项目 + 我的事项 | 本项目 | 执行、回填、上报 |

同一个页面组件，通过权限过滤数据范围，不做三套界面。

### 主线 4：双端联动

- **桌面端**：看全局、做决策、派单、审批。
- **移动端**：跑动签到、进展回填、快速审批、预警接收。
- 数据实时同步，**移动端的每一次回填都会即时改变桌面端的红黄灯状态**。这一点做到了，一线才有动力用；做不到，台账就会变成"周五下午补录"。

### 主线 5：经营例会一键成会

工作台本身就是会议材料。点"生成经营分析"，自动汇总：本期核心指标与偏差、红灯事项及责任人、上次例会议题的闭环情况、本期需决策事项。**上次会议定的事没办完，这次自动带出来**——这是让例会真正产生管理效力的机制。

### 主线 6：预警规则可配置

预警不能写死在代码里，要做成后台可配的规则表：

| 类别 | 指标 | 黄灯 | 红灯 |
|---|---|---|---|
| 手续 | 单项滞留天数 | 超期 7 天 | 超期 15 天 |
| 进度 | 里程碑偏差 | 滞后 7 天 | 滞后 15 天或影响交工节点 |
| 回款 | 应收逾期 | 逾期 30 天 | 逾期 90 天或单笔 > 500 万 |
| 资金 | 13 周最低余额 | 低于 4,000 万 | 低于 3,000 万 |
| 合规 | 证照剩余有效期 | 90 天 | 60 天 |
| 网约车 | 双证合规率 | 低于 95% | 低于 90% |
| 库存 | 车龄 / 物资呆滞 | 60 天 / 90 天 | 90 天 / 180 天 |
| 销售 | 月度目标达成预测 | 缺口 10% | 缺口 20% |

阈值前三个月按经验设，之后**根据"红灯数量"反向校准**：红灯天天超过 5 条就是设松了，一周不出红灯就是设严了。

## 五、建设路径建议

分三期，**不要一次性上全套**。

**一期（1-2 个月）· 让工作台先有用**
经营驾驶舱 + 跑动作战台 + 移动端回填。数据可以先手工/半自动维护——先把"卡点被看见、被派单、被闭环"这条链路跑通。这一期的价值最大，投入最小。

**二期（2-4 个月）· 打通业务数据**
接入四条业务线的核心系统（项目管理、财务、平台数据仓、DMS），实现 T+1 自动同步，上线四个业务专题页和预警规则引擎。

**三期（4-6 个月）· 做深分析**
资金 13 周预测、投资回报倒查、单车经济模型、健康度评分模型、经营例会自动成会。

## 六、几个容易踩的坑

1. **别做成大屏。** 大屏是给客人看的，工作台是给你自己用的。判断标准：这一屏能不能直接派单。
2. **别追求指标全。** 首页 KPI 超过 8 个，你就一个都不会看。宁可少而准。
3. **口径必须先统一再上线。** 尤其"收入"和"回款"，四条业务线的确认时点差别很大，口径不统一会导致数字被质疑，一旦被质疑系统就废了。
4. **一线不愿意填是最大风险。** 解法：移动端回填控制在 30 秒内；填了的人自动生成周报、少写材料；不填的事项自动升级暴露。用"填了有好处、不填有压力"来驱动。
5. **不要让工作台成为第二套台账。** 凡是能从现有系统抽的，一律抽；实在没有系统的（比如跑动、承诺、关系），才在工作台里原生录入。

## 七、v2.0 重大更新（科技感 UI 重构 + 三大能力补全）

在 v1 原型基础上，**对可运行工作台做了一次彻底的"科技公司化"重构**，并补齐了原设计中缺失的三块关键能力：项目要素梳理、合同全生命周期、业财一体。

### 7.1 主展示界面科技感重构（设计系统）

把原来偏"管理后台"的浅色界面，整体换成**深色科技风设计系统**，让经营驾驶舱与首页具备科技公司既视感：

| 设计要素 | 实现方式 |
|---|---|
| 深空底色 | `--bg:#05070f` 极深蓝黑，叠 `aurora` 极光径向渐变 + 44px 科技网格（径向遮罩渐隐），营造"数据中枢"氛围 |
| 玻璃拟态卡片 | `--panel:rgba(18,26,45,.72)` + 毛玻璃模糊 + 1px 青蓝描边 + 切角（cut-corner）造型，区别于普通方卡 |
| 霓虹辉光 | 主色青 `--cy:#00e5ff`、蓝 `--bl:#3b82f6`、紫 `--pu:#8b5cf6`；KPI 卡、标题、图表描边带 glow 辉光 |
| 等宽数字 | 全部金额/百分比用 `tabular-nums` 等宽字体，驾驶舱数字像"仪表盘"一样对齐跳动 |
| 状态脉冲 | 红黄绿状态点带呼吸/脉冲动画（`.done`/`.late`/`.todo`），异常一目了然 |
| 手绘 SVG 图表引擎 | 自研渐变填充 + 辉光滤镜 + 虚线网格的柱状/面积/甘特/漏斗/环形图（零外部依赖，契合科技感且离线可用） |
| 关系温度计 | 关键人卡片用 5 格热度条（`.heat`）表示关系紧密度，决策链用"决策/影响/执行"三色列呈现 |

**响应式**：桌面左侧固定导航 + 玻璃面板；移动端（<960px）切顶部汉堡 + 底部 5 Tab（驾驶舱/业务/跑动/合同/财务/项目），侧栏变抽屉、抽屉变底部菜单。断点 1180 / 980 / 860 / 400 四级。

### 7.2 项目中心：关键节点 / 关键人·联系人 / 相关公司 梳理

项目详情页升级为 6 个标签页（总览 / 关键节点 / 关键人·联系人 / 相关公司 / 项目合同 / 图纸·预算·概算），前三者是本次新增的"项目要素库"——把原来散在脑子里的"谁、什么单位、卡在哪"正式沉淀为结构化数据。

**关键节点（节点台账）**
- 时间线（`.tl`）+ 甘特双视图；节点含：名称、类别（手续/工程/商务/合规）、计划日、实际日、责任人、状态（已完成/滞后/待办）、风险提示。
- 支持新增/查看/标记完成/删除；滞后自动飘红并进入驾驶舱"今日必须处理"。

**关键人 · 联系人（人物库 + 决策链）**
- 决策链三列：决策层（D）/ 影响层（I）/ 执行层（E），呈现"这件事谁拍板、谁影响、谁落实"。
- 人物卡：姓名、单位、职务、角色标签、关系热度（5 格温度计）、最近联系时间、电话/微信、**联系记录时间线**（logContact：每次联络自动留痕）。
- 支持新增/查看/删除联系人，联系动作直接回填——让"跑动"从个人记忆变成组织资产。

**相关公司（企业台账）**
- 表格化维护：公司名、类型（业主/设计/施工/监理/供应商/政府/融资）、关联项目、对接人、金额（万元）、状态、备注。
- 支持新增/查看/删除；与合同、关键人互相穿透（从公司可看其合同与联系人）。

### 7.3 合同全生命周期管理（新增独立页 + 项目内嵌）

新增**经营中枢 › 合同管理**独立页，且每个项目详情内也有"项目合同"页，二者共用同一张合同表。合同对象含：编号、名称、相对方、方向（收/付）、金额、履约进度、质保金、签订日、计划收付款、变更签证、状态。

| 能力 | 说明 |
|---|---|
| 收付款计划 | 每笔分期含 序号/名称/比例/金额/计划日/实际日/状态，计划 vs 实际并排对比 |
| 变更签证 | 独立 `changes` 列表（事由、金额、日期、状态），影响合同额的变更单独留痕 |
| 履约进度 | 进度条 + 已收/应收、已付/应付实时汇总 |
| 逾期预警 | 根据"计划日已过且未实付"自动判定逾期，列表按 `逾期天数 × 金额` 排序优先暴露 |
| 质保金 | 单列质保金字段，到期释放提醒 |
| 结算/开票 | 抽屉内可登记结算进度、开票、回款动作 |
| 导出 | 一键导出合同台账 CSV（带 BOM，Excel 中文不乱码） |
| 新增合同 | 右侧抽屉表单录入，立即进入统计与预警 |

驾驶舱顶部 KPI 与"今日必须处理"直接消费合同逾期与收付款缺口，实现"看到问题→定位合同→派单催收/申报"的闭环。

### 7.4 业财一体完善（业务财务页重构）

**业务财务**页升级为 6 个 Tab，打通"合同 → 收入 → 开票 → 回款 → 成本 → 现金"的业财链路：

- **经营概览**：分业务线损益（pl）、现金安全线、关键比率。
- **应收**：按 30/60/90/180+ 账龄（ar），含逾期金额与账龄结构，下钻到合同。
- **应付**：按账龄（ap），含质保金与"可申报未申报"缺口提醒。
- **现金流**：12 月收入/开票/回款柱线 + **13 周资金预测**（周净流、期末余额、安全线跌破预警），并标出留抵退税等一次性流入。
- **税务**：增值税、所得税、留抵退税（如 210 万）单列，反映真实税负与现金流影响。
- **预算执行**：费用科目预算 vs 执行对比，超支飘红。

金额统一以**万元**口径，避免四条业务线单位混乱；所有数字与合同、项目双向穿透。

### 7.5 业务人员管理 + 业务费用（人员 · 项目 · 进度 · 关键人 · 费用 · 合同 一体化）

把"谁在跑、跑哪些项目、花了多少业务费、最终合同执行得怎样"整合到同一视图，解决管理者最关心的两个问题：**业务人员按情况（项目与进度）怎么排布**，以及**业务费用按人员/项目怎么归集**。

**数据模型（新增）**
- `staff`（业务人员，公司内部）：姓名、角色、业务线（新能源/大交通/网约车/车辆销售/综合）、电话、区域、状态（在职/试用/停职）、入职日、**负责项目列表**（与 projects 关联）。
- `expenses`（业务费用，单位：元）：关联业务人员 + 关联项目（可空）+ 关联合同（可选）、类型（招待费/差旅费/佣金提成/通讯交通费/其他）、金额、日期、状态（待审批/已报销/驳回）、说明。

**业务人员管理页（独立页 `p-staff`，经营中枢分组）**
- 顶部 KPI：业务人员数、负责项目（去重）、业务费用合计（待报销/已报销拆分）、关联合同额（收/付，万元）。
- 业务线筛选（全部/新能源/大交通/网约车/车辆销售/综合），联动人员卡片与费用统计。
- 人员卡片网格（`.scard`）：角色、业务线、状态脉冲点、负责项目数、投资额、关联合同（收）、业务费用合计；点开即详情。
- **业务费用总览**：状态筛选（全部/待审批/已报销/驳回）+ 按类型 donut 式横条 + 按业务人员横条 + 费用台账表；可一键导出 CSV（人员/费用两份）。

**业务人员详情抽屉（整合全景）**
- 档案（角色/业务线/状态/电话/区域/入职）；
- **负责项目与进度**：列出其项目、进度条、点击直达项目详情；
- **项目关键人**：聚合该人员所负责项目的外部关键决策人（决策/影响/执行）；
- **业务费用**：该人员全部费用表 + 合计；
- **关联合同执行**：其项目的合同（收/付、金额、履约进度、风险）；
- 快捷动作：派单督办、登记业务费用、编辑档案。

**项目详情新增「业务人员 · 费用」标签页**
- 展示本项目业务人员卡片、本项目业务费用台账（含合计/待审批），并支持**指派/调整业务人员**（多选项勾选，写回 `staff.projects`）与**登记本项目业务费用**。
- 由此实现闭环：项目 ↔ 业务人员 ↔ 关键人 ↔ 业务费用 ↔ 合同执行 互相穿透。

**金额口径说明**：业务费用按"元"列示（报销单天然单位），合同/财务仍按"万元"；两者在人员详情与项目页并排呈现，便于看"花了多少费用、换回多少合同额"。

## 八、可运行版本（PWA · 甘肃新煜科技工作台）

在第一版原型基础上，已交付一个**可直接运行的渐进式 Web 应用（PWA）**，命名 **甘肃新煜科技工作台**，可在 MacBook / 联想笔记本（Windows）/ 华为手机（Android/HarmonyOS）/ iPhone 上一致使用。

**目录**：`workbench-app/`
- `index.html` — 应用外壳（加载下列 CSS/JS，无外部 CDN 依赖，离线可用）
- `css/app.css` — 科技感深色设计系统（玻璃拟态、辉光、网格、切角卡、脉冲状态点）
- `js/data.js` — 数据层（v2 数据模型：项目/节点/人物/公司/合同/业财/跑动/审批，localStorage 持久化）
- `js/charts.js` — 手绘 SVG 图表引擎（柱状/面积/甘特/漏斗/环形/资金线，渐变+辉光）
- `js/modules.js` — 合同管理 + 项目详情全部能力模块（节点/人物/公司/合同/图纸预算概算）
- `js/app.js` — 核心逻辑（导航、驾驶舱、业务线、跑动作战台、业务财务、初始化）
- `manifest.json` — PWA 清单（名称、图标、standalone 显示，主题色已调为深色科技风）
- `sw.js` — Service Worker（离线缓存应用壳 v2，断网仍可打开，缓存已覆盖 css/js）
- `icons/` — 192/512 PNG + apple-touch-icon + favicon.svg

**界面与模块对应**
- 科技感 UI（§7.1）→ `css/app.css` + `js/charts.js`
- 项目要素梳理（§7.2 关键节点/关键人·联系人/相关公司）→ `js/modules.js` 的 `dtNodes/dtPeople/dtOrgs`
- 合同全生命周期（§7.3）→ `js/modules.js` 的 `renderContract/openContractView/settlePlan/openChangeAdd/exportContracts` + 页面 `p-contract`
- 业财一体（§7.4）→ `js/app.js` 的 `renderFin/renderFinBody`（pl/ar/ap/cash/tax 各 Tab）

**跨端运行方式**
- **MacBook / 联想笔记本（Windows）**：用 Chrome / Edge / Safari 打开 `index.html` 即可；也可 `python3 -m http.server` 起静态服务后访问，`http(s)` 环境下可"安装到桌面"并注册 Service Worker 获得离线能力。
- **华为手机（Android / HarmonyOS）**：Chrome 打开页面 → 菜单"安装应用"/"添加到主屏幕"，即生成桌面图标，作为 App 运行。
- **iPhone（iOS）**：Safari 打开页面 → 分享 →"添加到主屏幕"，生成桌面图标；`apple-touch-icon` 已配置，图标显示正常；四周安全区（刘海/底部）已用 `viewport-fit=cover` + `env(safe-area-inset-*)` 适配。

**响应式适配要点**
- 桌面（≥960px）：左侧固定玻璃导航栏；移动端（<960px）：顶部汉堡栏 + 底部 5 个 Tab（驾驶舱/业务/跑动/合同/财务/项目），侧边栏改为抽屉浮层。
- 表格横向滚动、卡片单列堆叠，触控目标足够大。

**数据持久化**
- 所有录入（关键节点/关键人/相关公司/合同/图纸预算概算/跑动事项/派单/审批）写入浏览器 `localStorage`（键 `xy_workbench_v2`），刷新与重开不丢失；首次加载注入示例数据。
- 说明：localStorage 为单机单浏览器存储，适合管理者自用与演示；若要多人协同，需接入后端（二期目标，详见第五章）。

**交互闭环**
- 与原型一致：预警 → 下钻 → 派单 → 跑动留痕 → 回写。合同逾期/收付款缺口、超概/错版等风险，通过驾驶舱预警、合同逾期排序、概预算对比与状态标签可视化闭环。

## 八、v4.0 重大更新（2026-08-08）

在 v3.0（业务人员管理与业务费用整合）基础上，新增四类能力：项目地图与数字孪生、业务费用并入损益口径、人员绩效排名、登录与多设备协同后端。

### 8.4 登录与多设备协同（`server/server.js` + `js/app.js` 的 `SYNC/doLogin/startStream`）
- **零依赖 Node 后端**：`node server/server.js`（默认 8090）。提供静态托管 + 登录鉴权 + 共享数据 + SSE 实时广播。
- **协同机制**：登录后，任意一端保存（新增/编辑项目、合同、人员、费用、派单等）即通过 `fetch('/api/db')` 推送并广播；其他在线设备经 `EventSource('/api/stream)` 实时刷新；顶部与侧栏显示"协同中 + 在线成员"。
- **多端适配**：MacBook / 联想 Windows / iPhone / 华为 打开同一地址即可协同编辑与联动。
- **离线兜底**：未登录或单独打开 PWA 时，完全使用本机 `localStorage`，数据不跨设备；联网登录后自动并入共享副本。`sw.js` 已对 `/api/*` 放行（不缓存）。

**数据持久化（v4 修正）**
