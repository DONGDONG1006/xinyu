# 甘肃新煜科技工作台 · 运行与安装说明（v6.6）

纯前端 PWA（零外部依赖），黑 + 橙科技主题、明暗主题自适应、品牌 LOGO。支持**账号密码登录 + 管理员权限体系 + 双平台界面
（业务人员平台 / 管理层平台）+ 内置 AI 助手**，可长期单机使用，也可多设备实时协同；
兼容 Mac / Windows / iPhone / 华为 / 任意现代浏览器；可部署到外部网络，可安装为独立 APP（PWA 或桌面客户端）。

---

## 一、四种使用方式一览

| 方式 | 适用场景 | 多设备协同 | 离线 | 独立 APP 形态 |
|------|----------|-----------|------|--------------|
| ① 浏览器直接打开 | 临时查看 / 演示 | 否 | 是（file:// 受限于 Service Worker） | 标签页 |
| ② 本地协同服务（推荐） | 日常办公 / 多设备联动 | **是** | 是（缓存壳） | 浏览器 + 可"安装" |
| ③ 安装为 PWA 独立 APP | 手机/电脑长期用 | 是（同地址） | 是 | 桌面/主屏独立图标 |
| ④ 桌面客户端（Electron） | 想要真·双击运行 | 是 | 是 | .app / .exe |

> 数据默认存本机 `localStorage`（键 `xy_workbench_v4`）；用方式②/③/④连上协同服务后，
> 任意设备保存的数据会实时同步到其它设备（共享副本落 `server/db.json`）。

## 一之二、⚡ 快速开始（手机安装 & 业务人员登录）

### A. 在手机上打开并"安装"到桌面
1. 先把工作台放到手机能访问的地址（任选其一）：
   - 电脑启动协同服务：`node ../server/server.js`，手机连同一 WiFi，访问 `http://<电脑内网IP>:8090`；
   - 或部署到公网 / 域名（见第四节），手机用公网地址访问。
2. **iPhone / iPad（Safari）**：打开地址 → 点底部「分享」按钮（方块带向上箭头）→ 选「添加到主屏幕」→ 命名「新煜工作台」→ 添加。主屏出现独立图标，点开即以全屏 APP 运行。
3. **安卓（Chrome）**：打开地址 → 点右上角「⋮」→「安装应用」/「添加到主屏幕」→ 确认。桌面出现图标。
4. 安装后即为独立 APP：支持离线、全屏、无浏览器地址栏；登录一次后下次直接进。
> 没有服务器也行：把 `workbench-app/` 整目录传到手机，用支持 PWA 的浏览器打开 `index.html` 即可用（仅本机、无协同）。

### B. 给业务人员开通账号并登录
1. 管理员用 `admin / admin888` 登录 → 左侧「系统 → 平台管理后台 → 用户管理 → ＋ 开通账号」。
2. 填「登录账号 / 姓名 / 角色（选 **成员**）」，**保持勾选**"首次登录由本人设置密码"→ 点「开通账号」。
3. 把生成的「登录账号」发给该业务人员（无需发密码）。
4. 业务人员打开工作台 → 登录页输入账号 → 因是首次登录，自动跳到「设置密码」页 → 自设 6 位以上密码 → 进入**业务人员平台**（跑动作战台 / 合同 / 人员 / 项目 / 地图）。
5. 之后该业务人员用「账号 + 自己设的密码」正常登录即可。
> 忘记密码：管理员在「用户管理」点「改密」重置；想停用其账号点「禁用」。成员无权限时会提示「需要管理者及以上权限」。

## 二、方式①：浏览器直接打开（最快）

直接双击 `index.html` 用 Chrome / Edge / Safari 打开即可。
- 首次进入弹出**账号登录**网关，使用默认账号登录（见第五节）。
- 本机数据存浏览器本地，换浏览器/清缓存会丢，重要数据请用管理后台「导出全部数据」备份。
- 注意：`file://` 下 Service Worker 可能不生效，离线能力以方式②/③最佳。

## 三、方式②：本地协同服务（推荐，多设备联动）

```bash
# 进入项目目录
cd workbench-app
# 启动零依赖 Node 协同后端（默认端口 8090，可用 PORT 环境变量覆盖）
node ../server/server.js
# 或
PORT=8090 node ../server/server.js
```

启动后访问：
- 本机：http://localhost:8090
- 同局域网手机/其它电脑：http://<本机内网IP>:8090
- 在任意设备登录同一后端地址，保存即实时同步（SSE 广播）。

**关闭**：`Ctrl+C` 停止服务。共享数据在 `../server/db.json`。

## 四、外部网络 / 云端部署（让外网也能用）

协同服务已 `listen(0.0.0.0)`，天然可被外部访问。三种暴露方式：

1. **内网穿透（最快验证）**：用 `ngrok` / `frp` / `cloudflared` 把 8090 端口映射到公网临时域名。
2. **云服务器**：把整个 `workbench-app/` + `server/` 传到任一 Linux 云主机，
   `node server/server.js` 后台常驻（建议用 `pm2` 或 `nohup`），开放安全组 8090 端口，
   用 `http://<云主机公网IP>:8090` 访问。
3. **域名 + HTTPS（生产）**：在 Nginx/Caddy 前加反向代理并配证书，把根路径反代到
   `http://127.0.0.1:8090`。HTTPS 下 PWA 可安装、Service Worker 正常。示例（Nginx）：

```nginx
server {
  listen 443 ssl; server_name wb.your-domain.com;
  ssl_certificate     /path/fullchain.pem;
  ssl_certificate_key /path/privkey.pem;
  location / {
    proxy_pass http://127.0.0.1:8090;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;     # 用于 SSE 长连接
    proxy_set_header Connection "keep-alive";
    proxy_set_header Host $host;
  }
}
```

> 任一设备只要打开同一地址并登录，即为同一协同空间。把该地址发到团队即可全员使用。

## 五、账号体系（双平台 + 管理员开通 + 首登设密）

平台按角色进入**两套界面**：
- **管理层平台**（管理员 / 管理者）：经营驾驶舱、四条业务线、合同 / 财务 / 跑动 / 人员 / 地图 / 项目详情 + 平台管理后台。
- **业务人员平台**（成员）：聚焦本人业务的跑动作战台、合同管理、业务人员、项目详情、项目地图。

默认账号：

| 账号 | 密码 | 角色 | 平台 | 权限 |
|------|------|------|------|------|
| `admin` | `admin888` | 管理员 | 管理层 | 全部权限（用户管理、系统设置、数据维护） |
| `manager` | `manager888` | 管理者 | 管理层 | 业务增改删、目标设置（不含用户/系统级） |
| `member` | `member888` | 成员 | 业务人员 | 查看 + 跑动/费用填报 |

**业务人员账号由管理员开通**：管理员在「平台管理后台 → 用户管理 → ＋ 开通账号」新建成员账号，
默认勾选"首次登录由本人设置密码"，账号即开通使用权限；该成员**首次登录**时会被引导设置自己的登录密码，
设置完成后方可进入业务人员平台。未开通前无法登录。

- 登录入口：首次进入自动弹出；已登录后右上角点用户名可退出。
- 角色权限矩阵见「平台管理后台 → 权限矩阵」页。
- 任何破坏性操作（新增/删除项目、合同、人员等）按角色门禁，越权会提示所需权限。

## 六、方式③：安装为 PWA 独立 APP

满足「独立 APP 软件」需求，全程离线可用、带独立图标。

- **电脑（Chrome / Edge）**：打开地址（方式②/④）→ 地址栏右侧「安装」图标 / 菜单「应用 → 安装此站点为应用」→ 桌面出现独立图标，双击即以无地址栏的独立窗口运行。
- **iPhone / iPad（Safari）**：分享 → 「添加到主屏幕」→ 主屏出现图标，作为独立 APP 打开。
- **华为 / 安卓（Chrome）**：菜单「安装应用」/「添加到主屏幕」。

> 安装后即为独立 APP，支持离线、推送通知（预留）、全屏运行，体验等同原生。

## 七、方式④：桌面客户端（Electron，真·双击运行）

已内置 `desktop/` 外壳，把 Web 工作台包成 Mac `.app` / Windows `.exe` / Linux `AppImage`。

```bash
cd workbench-app/desktop
npm install          # 安装 electron
npm start            # 开发预览（自动拉起协同后端并打开窗口）
# 打包发布：
npm install -g electron-builder
npm run dist         # 在 dist/ 生成各平台安装包
```

- 启动时会自动拉起 `server/server.js`（端口 8090），因此桌面客户端天然支持多设备协同。
- 后端未就绪时自动回退到本地 `index.html` 离线运行，保证一定能打开。

## 八、管理员功能（平台管理后台）

左侧「系统 → 平台管理后台」仅管理员可见，包含：
- **用户管理**：新增/重置密码/启用禁用/删除账号（自带的账号也在此管理）。
- **权限矩阵**：成员 / 管理者 / 管理员 三级权限对照。
- **年度目标**：营收 / 回款 / 净利 / 装机目标设置（实时影响驾驶舱仪表）。
- **系统设置**：导出全部数据（JSON 备份）、导入数据、恢复示例数据。
- **登录审计**：全员登录时间、账号、角色、设备记录（最多保留 200 条）。

破坏性操作（新增/删除项目、合同、人员等）已按角色门禁：成员无权限会提示「需要管理者及以上权限」。

## 九、AI 智能助手（内置，离线可用）

右下角 🤖 浮动按钮唤起 AI 助手，可**协助使用者对平台功能与信息进行查询、编辑与处理**：

- **查数据**：「本月营收多少」「应收多少」「司机合规率」「XX 项目进度」「人员绩效排名」等，直接基于平台实时数据回答。
- **办业务**：说「新增一个风电项目 / 加个合同 / 添加业务人员 / 记一笔跑动」，助手会打开对应表单并预填名称，确认即保存（受角色权限门禁约束）。
- **出报告**：「生成周报」一键生成当前项目经营周报草稿。
- **找功能**：「打开合同管理」「进入经营驾驶舱」直接跳转对应界面。
- **上手引导**：「你能做什么」列出全部能力；面板内置快捷指令 chips。

**两种引擎**：
1. **本地意图引擎（默认）**：纯前端规则 + 平台数据，离线、免密钥、零成本，覆盖上述全部能力。
2. **云端大模型（可选）**：管理员在「平台管理后台 → 系统设置 → AI 助手」填入 OpenAI 兼容接口地址 / 模型 / Key 即可启用，获得更强对话与写作能力；不配置则始终走本地引擎，数据安全不出本机。

## 十、数据安全与长期维护

- **备份**：管理后台「导出全部数据」生成 JSON，随时可「导入」恢复。
- **版本**：Service Worker 缓存键 `xy-workbench-v6.5`，升级后自动清理旧缓存。
- **扩容**：业务数据全在 `DB` 对象（localStorage / db.json），结构变更由 `ensureV5` 自动补字段，老数据不丢。
- **迁移**：把 `workbench-app/` 整目录 + `server/` 目录拷到新机器即可，`server/db.json` 为共享数据。

## 十二、费用报销与审批流（出差 / 招待 / 报销 · v6.3 新增）

参考主流差旅申请、费用报销流程，新增"申请 → 审批"闭环：

- **业务人员平台 · 费用报销**：业务人员进入「费用报销」页，可提交三类申请并跟踪进度：
  - **出差申请**：业务线 / 关联项目 / 目的地 / 起止日期 / 交通工具 / 预估交通·住宿·补贴费。
  - **招待申请**：招待对象 / 人数 / 预估费用 / 事由。
  - **报销申请**：可关联已通过的出差或招待申请（可选），按 交通费 / 住宿费 / 餐饮招待费 / 办公及其他 填列明细并自动合计，支持借款抵扣；列表与审批中心均可导出台账。
  - 列表按"全部 / 待审批 / 已通过 / 已驳回"筛选，状态色标（待审批黄、已通过绿、已驳回红）；点开可见申请详情与"提交 → 审批"流程时间线。
- **管理层平台 · 审批中心**：管理者 / 管理员进入「审批中心」，查看待我审批及全部申请，单条**通过 / 驳回**（驳回须填原因），审批意见与审批人留痕并写入登录审计；列表可按状态筛选、可导出。
- **权限**：费用报销申请全员可提交；审批仅管理者 / 管理员可见可操作（成员越权会提示"需要管理者及以上权限"）。
- **登录安全**：登录界面不再显示默认账号 / 密码，避免凭据泄露；业务人员账号由管理员在「平台管理后台 · 用户管理」开通，首次登录自行设密。

## 十三、合同编号自动生成（按年份·业务线 · v6.4 新增）

在「合同管理」中，合同编号按 **年份 + 时间 + 业务线** 自动生成，贴合企业对合同编码的常规管理习惯：

- **编码规则**：`XY-<业务线前缀>-<YYYYMM>-<当年序号>`
  - `XY`：甘肃新煜（公司标识）
  - `<业务线前缀>`：按四条业务线区分 —— 新能源项目 `NY`、大交通机电 `JT`、网约车平台 `YC`、新能源车销售 `XS`
  - `<YYYYMM>`：签订日期的年份与月份（体现"年份与时间"）
  - `<当年序号>`：同一业务线、同签订年份内自增的序号（如 `001`、`002`…）
  - 示例：`XY-NY-202608-003`（新能源项目，2026 年 8 月签订的第 3 份合同）
- **新建合同自动赋值**：打开「＋ 新增合同」时，系统按所选业务线 + 签订日期实时算出编号并填入；切换业务线或修改签订日期会自动重算，也可点「↻ 重新生成」手动刷新。
- **业务线字段**：新增「业务线」下拉（新能源项目 / 大交通机电 / 网约车平台 / 新能源车销售）；存量合同在首次打开时按"关联项目类型 / 合同类别"自动补齐业务线，合同列表与详情均展示业务线标签。
- **修改权限（仅管理者）**：合同编号的修改权限于 **管理者及以上**（管理员 / 管理者）。普通业务成员无"编辑合同"入口，且任何角色修改编号时系统都会校验唯一性，重复编号会被拦截。
- **导出**：合同台账 CSV 已增加"业务线"列。

所需文件均在仓库 `server/` 与 `server/deploy/`：

| 文件 | 作用 |
|------|------|
| `server/server.js` | 零依赖协同后端（静态托管 + 登录 + SSE 实时广播 + `db.json` 持久化），支持 `PORT` / `DB_PATH` 环境变量 |

| `server/deploy/xinyu-workbench.service` | systemd 单元（开机自启、崩溃重启） |
| `server/deploy/nginx-xinyu.conf` | 域名 + HTTPS 反代（已含 SSE 关键配置：`proxy_buffering off`） |
| `server/deploy/deploy.sh` | 一键编排：有 Docker 走容器，否则走 Node + pm2 |

**Docker 方式（推荐，任意云主机）**
```bash
# 在仓库根目录执行（自动构建镜像并后台运行，映射 8090，数据落到卷）
docker compose -f server/deploy/docker-compose.yml up -d --build
# 开放安全组 8090 端口后，访问 http://<公网IP>:8090
```

**或直接用脚本**
```bash
bash server/deploy/deploy.sh        # 自动选 Docker / Node+pm2
```

**systemd 方式（裸机 Node）**
```bash
sudo cp server/deploy/xinyu-workbench.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now xinyu-workbench
# 日志：sudo journalctl -u xinyu-workbench -f
```

**域名 + HTTPS（生产）**：按 `server/deploy/nginx-xinyu.conf` 配 Nginx，再 `sudo certbot --nginx -d 你的域名` 自动签证书。HTTPS 下 PWA 可安装、Service Worker 正常。

**健康检查**：`curl http://<公网IP>:8090/api/ping` 返回 `{"ok":true}` 即正常。

#### 已部署的 CloudStudio 静态站点如何接入云端同步

上面的公网链接（CloudStudio）是**静态托管**，默认本机离线。要让它跨设备同步，两种接法：

- **接法①（最简）**：直接把后端部署到你的服务器，用 `http://<公网IP>:8090` 当工作台地址（前端 + 同步同源，无需额外配置）。
- **接法②（静态站 + 独立后端）**：保留 CloudStudio 静态链接，在 App 内 **管理员登录 → 平台管理后台 → 系统设置 → 协同服务地址** 填入 `http://<公网IP>:8090` 并保存，所有设备即指向你的云端后端实时同步。

> 顶栏状态实时显示连接情况：`⦿ 云端同步已连接`（绿）/ `⦿ 同步连接中…` / `⦿ 本地离线`（琥珀，数据仅存本机）。

#### 方案 C：平台托管（Railway / Render / Fly.io）★ 无需自建服务器

不想维护 VPS？用这些平台托管后端，几分钟拿到公网地址，数据统一存于平台持久卷：

| 平台 | 配置 | 持久化 | 备注 |
|------|------|--------|------|
| **Railway** | `server/deploy/railway.toml` | 持久卷 `/data` | 免费额度够用，健康检查 `/api/ping` |
| **Render** | `server/deploy/render.yaml` | 挂载盘 `/data`（Free 若无磁盘则为临时盘，需定期导出备份） | 新建 Blueprints 连仓库自动识别 |
| **Fly.io** | `server/deploy/fly.toml` | 持久卷 `xinyu_data` | 部署前需 `fly volumes create xinyu_data` |

**通用步骤**：
1. 把 `server/` 与 `workbench-app/` 推到 GitHub 仓库（平台从 Git 拉取源码）。
2. 按各平台指引连接仓库并部署（Railway / Render 读配置文件自动构建；Fly 用 `fly deploy`）。
3. 平台分配公网域名（如 `https://xinyu-workbench.up.railway.app` / `*.onrender.com` / `*.fly.dev`）。
4. 把该域名填入 App：**管理员 → 平台管理后台 → 系统设置 → 协同服务地址** → 保存，所有设备即指向云端后端实时同步。
5. 验证：`curl https://你的平台域名/api/ping` 返回 `{"ok":true}`。

> 平台托管域名与 CloudStudio 静态链接二选一：要么直接用平台域名作为工作台地址（前端 + 同步同源，最简），要么保留 CloudStudio 静态链接、仅把平台域名填为协同地址。
